# Asia Motors: новий інтернет-магазин

Новий дизайн і фронтенд інтернет-магазину автозапчастин Asia Motors (https://asia-motors.in.ua/ua/).

**Стек:** Next.js 15 (App Router, серверний рендеринг), React 19, TypeScript, чистий CSS із дизайн-токенами.
Next.js обрано тому, що сторінки каталогу й товарів рендеряться на сервері: це потрібно для SEO, а фільтрація великого каталогу працює без важкого клієнтського бандла.
API-маршрути дають місце для серверного оформлення замовлень, де не світяться секретні ключі.

## Запуск

```bash
npm install
cp .env.example .env.local      # заповніть SITE_URL і канал доставки замовлень
npm run import:catalog -- ./export.xml   # імпорт каталогу Asia Motors (див. нижче)
npm run build && npm start      # http://localhost:3000
# або npm run dev для розробки
```

## Звідки беруться дані

На сайті немає жодного вигаданого товару, ціни, контакту чи умови. Усе береться з двох файлів:

| Файл | Вміст | Як заповнити |
|---|---|---|
| `data/catalog.json` | категорії, товари, ціни, фото, характеристики, сумісність, наявність | `npm run import:catalog -- <файл або URL>` |
| `data/store.json` | телефони, e-mail, адреси, графік, соцмережі, способи доставки й оплати, тексти сторінок «Доставка», «Оплата», «Гарантія», «Повернення», «Про нас» | вручну, текстом з оригінального сайту |

Обидва файли перечитуються автоматично, коли змінюються (кеш сторінок оновлюється до 5 хвилин), тож після повторного імпорту перезбирати сайт не потрібно.

Якщо якогось поля немає, сайт його не показує. Наприклад, без телефону зникає блок телефону в шапці, а без способів оплати зникає крок «Оплата» в оформленні.

### Імпорт каталогу

`scripts/import-catalog.mjs` приймає:

- **YML/XML-фід** (`yml_catalog`). Це стандартний експорт Horoshop, OpenCart, Prom.ua та Rozetka. Скрипт переносить категорії з вкладеністю, `name`, `vendorCode`, `vendor`, `price`/`oldprice`, `available`, `picture` (кілька фото), `description` і `param`;
- **CSV** з роздільником `,` або `;`. Колонки розпізнаються за назвою (укр./рос./англ.): Назва, Артикул, Ціна, Стара ціна, Виробник, Категорія (шлях `Двигун > Фільтри`), Фото, Наявність, Опис, Сумісність. Усі інші колонки стають характеристиками.

Параметри з назвами на кшталт «Сумісність», «Застосовність» або «Марка авто» стають блоком **сумісності**, а з нього береться фільтр «Марка авто».
HTML опису очищується: скрипти, стилі й обробники подій вирізаються.

Фільтри будуються лише з полів, які справді заповнені в товарах: ціна, наявність, виробник, марка авто, а також до 8 характеристик, що мають від 2 до 40 різних значень.

### Логотип

Поки що використовується текстовий знак «Asia Motors». Покладіть оригінальний файл логотипа в `public/` і вкажіть його в `data/store.json → "logo": "/logo.svg"`.

## Оформлення замовлень

`POST /api/order` перевіряє форму, **перераховує суму за цінами каталогу на сервері** (ціни з браузера ігноруються) і передає замовлення в налаштовані канали:

- `ORDER_WEBHOOK_URL`: JSON-замовлення POST-запитом. Якщо задано `ORDER_WEBHOOK_SECRET`, запит підписується HMAC-SHA256 у заголовку `X-Signature-SHA256`. Через вебхук можна підключити CRM, адмінку Horoshop/OpenCart (через проміжний скрипт), Make або n8n;
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`: повідомлення менеджеру в Telegram.

**Якщо жоден канал не налаштовано, кнопку «Підтвердити замовлення» вимкнено, а користувач бачить попередження**, що онлайн-оформлення не підключене. Сайт не імітує прийняте замовлення.

## Структура

```
src/app/            сторінки: головна, /catalog, /catalog/[slug], /product/[slug], /search,
                    /cart, /checkout, /info/[slug], /contacts, API, sitemap, robots
src/components/     Header, CatalogMenu (мега-меню), MobileMenu, SearchBox (підказки),
                    ProductCard, ListingView, Filters, Gallery, Tabs, AddToCart, Footer…
src/lib/            catalog.ts (дані), listing.ts (пошук/фільтри/сортування),
                    cart.ts (кошик у localStorage), order.ts (валідація), order-delivery.ts
scripts/            import-catalog.mjs
tests/              e2e.mjs + тестовий фід (лише для перевірки, позначений «[ТЕСТ]»)
```

## Тести

```bash
npm run test:e2e
```

Скрипт генерує **тестовий** фід (`tests/.out`, назви «[ТЕСТ]…», артикули `TEST-xxxx`), збирає на ньому сайт, піднімає приймач вебхука і проганяє в Chromium 57 перевірок.
Перевіряються пошук, підказки, мега-меню, фільтри, сортування, пагінація, сторінка товару, кошик і перерахунок суми, валідація форми, доставка замовлення у вебхук із підписом, захист від підміни ціни, 404, мобільне меню, фільтри на смартфоні та відсутність горизонтальної прокрутки на 390 px і 820 px.
Скриншоти зберігаються в `tests/.out/shots`.
Після тестів виконайте `npm run build`, щоб зібрати сайт на робочих даних.
